# Pilot v0 报告（2026-11-06；契约 v7；不入主分析）

范围：Claude 4 臂（Sonnet 5.5 / Opus 5.5 × medium / high）× 2 个任务（c01-reach、c02-avoid）× 2 个检查点（S1 weak_axis seed1、S2 seed1）× 1 次重复 × R=4。共 16 个 run、64 个回合，原始记录在 `runs/pilot-v0/a1/`，汇总 `runs/SUMMARY/pilot-v0-a1.{json,md}`。**用途只有三个：定成本、筛任务带、找工程缺陷**（预注册 K-S3-11）；每格只有 1 个检查点 × 1 次运行，**没有统计推断力**。

## 1 执行事实
- 16/16 run 状态 verified；工具审计全部通过；完成率 100%；无输出预算耗尽、无无块、无被跳过语句、无限额中断。
- CLI 报告成本合计 $5.31（Sonnet $1.45、Opus $3.87）；输出 127,376 token（含思考）。单 run：Sonnet $0.14–0.34，Opus $0.35–0.83；最贵最慢的是 Opus·high 在 c02-S2（28,556 输出 token，302 s，$0.83）。
- 用户额度读数：批前 5h≈20%/周≈10%；批 1 后 ≈35%/≈18%；批 2 后待读（读数含主会话自身消耗，无法拆分）。

## 3 发现（每条都是“Pilot 观察”，不是结论）
1. **c01 饱和**：四个臂都回到 ≈1.00，与最好的对照持平，无区分度；该任务只能当流程健全性检查。
2. **c02 S1**：Opus（+0.40）高于 gain_greedy（+0.28）、闭式解（+0.16），**甚至高于神谕还原（+0.23）**——即超过了“恢复原始健康策略”，说明编辑不止是修复；Sonnet（+0.26–0.34）≈ gain_greedy。
3. **c02 S2（自然故障）**：Opus 隐藏 ID 0.92–1.00（+0.71…+0.78），明显高于最强简单对照 gain_greedy（+0.35）；**Sonnet 仅 +0.13，且 Regression 高达 0.60–0.84**（把原来成功的 episode 改坏）。
4. **机制不同**：Opus 在 c02-S2 上**整体重写网络**为手工控制器（PD + 障碍物分区门 + 预测偏移，53+29 条语句，frac_changed=1.0）；Sonnet 写了忽略障碍的简单 PD，开发集成功率在 0.0–0.44 间来回。这属于“神经电路合成”而非“修复”，按设计 §14.2 须单独命名，并解释了为何成功率可超过脚本专家的 ~0.8“上限”（该上限只是启发式专家的水平，不是任务上限）。
5. **推理强度**：本批里 high 没有带来更好的结果（Opus S2：medium 0.78 vs high 0.71；S1 两者持平；Sonnet 两档持平），但 high 更贵更慢；与 H2“非单调”相容，**但样本太小，不能写成结论**。
6. **停止行为**：开发集 16/16 后，模型在后续轮次提交空块（c01 大多只有第 1 轮有效）。协议允许，不算失败；意味着 R=4 在容易任务上用不满。

## 4 发现的工程/设计问题
- **输出上限逼近**：最大输出 28,556 token，离 32,000 上限只差 11%；更难的任务（c03/c04、Meta-World）可能被截断。→ 主实验把上限提高并做灵敏度子实验（H2 辅助实验）。
- **c01 无区分度**：主研究应降低 c01 的权重或仅作健全性检查；S3 尚未被 LLM 测试。
- **frac_changed=1.0 的补丁**（整体重写）需要在分析里单独标注编辑机制（缩放 / 局部 / 整体重写），否则“稀疏度”指标会被误读。
- **每格 n=1**：任何臂间差异（尤其 Sonnet vs Opus）都需要多检查点、多重复才能判断。

## 5 对主研究规模的含义（待用户额度读数校准）
- 单 run 平均 $0.33（R=4）；R=6、更难任务预计 $0.5 量级。“精简档”（144 run，R=6）≈ $70 的 CLI 报告成本，按批 1 的额度/成本比（+15% 5h、+8% 周，含主会话）估算会超过一周额度，**需要分多周或缩减**；“最简档”再扩一倍（≈32 run）≈ $11–16。
- 建议下一步（仍属 Pilot 性质，需用户同意）：①补 c03-hold、c04-delay 与 S3（每类 1 个检查点）各 1 次，看区分度与截断；②再决定精简档的任务与检查点数量，并冻结预注册。

观察：
1. **c03 S2**：Sonnet 稳定优于两个简单对照（+0.45 对 +0.05/−0.05），Regression=0。
2. **c04 S1：推理强度这次有差别**（high +0.53 = 神谕，medium +0.05），与 c01/c02 里“high 无增益”相反；单格单次，只说明 H2 需要多检查点才能判。**且 OOD 无迁移**（ΔOOD ≈ −0.07：延迟 6 的隐藏变体上没有改善）。

4. **“不编辑”也是一种合法且有信息的行为**：medium 档在已健康的策略上拒绝编辑，保住了成功率；应在分析里单列“放弃率”。

## 附 3：构念效度补强（P0）对 Pilot 的重新解读（契约 v8；不耗额度）
**A1 编辑机制分类**（27 个 Pilot LLM run，`runs/SUMMARY/mechanism-*.csv`）：
| 臂 | 整体缩放 scale | 整体重写 rewrite | 局部 local | 混合 mixed | 不编辑 |
|---|---|---|---|---|---|
| Sonnet·medium（8） | 4（ΔID +0.22） | 2（+0.34，Regression 0.30） | — | 1（+0.45） | 1 |
| Sonnet·high（8） | 4（+0.32） | 4（+0.35，Regression 0.21） | — | — | — |
| Opus·medium（7） | 4（+0.48，Regression 0） | 1（+0.78） | 1（+0.41） | 1（**−0.06**，Regression 0.32） | — |
| Opus·high（4） | 2（+0.41） | 1（+0.71） | — | 1（+0.54） | — |
**读法：14/27（52%）的 Pilot run 是纯整体缩放**，增益 +0.22…+0.48，落在 `gain_greedy`/`tensor_gain_greedy` 这类低维对照能覆盖的范围；真正的“整体重写”8 个，增益最高（到 +0.78），但 Sonnet 的 Regression 高达 0.21–0.30。构念上，两类要分开命名与排名。
**A2 编译式 PD 控制器（确定性、无 LLM，从全零网络写入）**：c01-reach ID/OOD = 1.00/1.00，c03-hold = 1.00/1.00，**c02-avoid 0.01/0.00，c04-delay 0.00/0.00**。→ **c01 与 c03 的功能复杂度太低**（一个线性 PD 编译进权重就满分），Claude 在这两个任务上的高分说明不了“权重编程能力”；有区分度的是需要避障逻辑与延迟预测的 c02 与 c04（编译式 PD 在那里为 0）。
**A6 泄漏审计**：对 27 个 Pilot LLM run 的提示与原始事件流审计，工具/MCP/斜杠命令/技能列表全为空；一个早于工作目录修复的 smoke run 因旧目录名含任务/类别词而**应判 invalid**（本来就不入主分析）；审计现已自动并入每个 run 的收尾，命中即标 identity_leak。
**对主研究的约束**：①主要比较放在 c02/c04/Meta-World，c01/c03 只作健全性检查；②头条结论按机制分层（scale / rewrite 分开）；③相对对照的比较要包含 compiled_pd 与 tensor_gain_greedy。
