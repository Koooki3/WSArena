## 1. 额度预算与分档（K-S0-05）
### 1.1 每个 run 的量级估算（假设，E3 将实测替换）
- c01（866 参数）首轮提示约 8k 输入 token；R 轮累计输入 ≈ R×(8k+…)≈ 40–60k（R=4）；输出（含思考）medium 约 5–10k/回合、high 约 15–25k/回合（MIT 的 Astra·xhigh 单次输出 20–29k 为参照）。
- ⇒ 每个 run（R=4）约 7–14 万 token；Opus 在订阅额度里的折算权重高于 Sonnet，**折算系数未知，只能实测**。
- 单任务 R=8 的 run 约翻倍。

### 1.2 三档（候选；以 E3/E4 实测的“每回合占窗口百分比”定档）
| 档 | 设计 | run 数 | 回合数 |
|---|---|---|---|
| 最简（Pilot） | 4 臂 × {c01,c02} × {S1-weak_axis s1, S2 s1} × 1 重复，R=4 | 16 | 64 |
| 精简（主研究候选 A） | 4 臂 × {c01,c02,c03} × {S1, S2, S3} × 2 检查点种子 × 2 重复，R=6 | 144 | 864 |
| 全量（任务书原规模，**仅在有 API 额度时**） | 2 模型 × 3 effort × 6 任务 × 3 种子 × 3 重复，R=8 | 324 | 2,592 |

全量需要的额度远超 Pro 的 5h/周窗口，只作为“若换 API/更高额度”的上限；**本期不做**，并如实写进报告的局限。

### 1.3 额度纪律（全局 CLAUDE.md，只能更严）
- 读不到 `get_usage` → 并行 ≤1；批量小；每批前后请用户读 5h/周百分比并写入 `QUOTA_LOG.tsv`。
- 5h 窗口 ≥80% 不派新批；周 ≥70% 只做收尾与验收；≥85% 全停。始终留 ≥15% 窗口给主会话。
- 一批 = 运行器一次调用（`--max-runs N`）；触限即停，不重试；知道重置时间就把下一批排到重置后。
- 不设 cron/守护进程（需用户另行批准）。
- 窗口耗尽时停在 run 边界之外也安全：回合级保存+重放保证“续跑零重复调用”。

## 2. Pilot 要回答什么（E3–E4）
1. **可行性**：4 臂能否稳定产出可解析 edits；失败类型分布（输出预算耗尽 vs 无块 vs 全被跳过）。
2. **成本**：每回合 token（输入/输出/思考）与窗口百分比；effort 对输出长度的影响；→ 外推 §1.2。
3. **区分度**：对照臂（null/random/oracle/analytic）与 LLM 的位置；任务/检查点 SR 带是否合适（天花板/地板）。
4. **隔离**：探针确认无泄漏、无工具；首个真实 run 的原始事件流审计。
5. **噪声**：`noise_floor` 在 5 个互不相交集合上的 SR 标准差 → 预注册判定带宽。
Pilot 结果**只用于定成本、筛任务带和改工程缺陷**，不得用来挑对某个模型有利的任务后当作“未经选择的主实验”（K-S3-11）。

## 3. 主研究设计要点（预注册时冻结）
- **臂**：Sonnet 5.5·medium / ·high，Opus 5.5·medium / ·high（`--effort medium|high`；允许值与行为以 E2 探针为准，写入预注册前不假设）。
- **自变量**：模型 × effort（Native Effort 比较）；固定交互预算（轮数、反馈、探针）作主协议；Matched-budget 比较用实测 token/墙钟。
- **因变量**：见 DESIGN §8。主终点 = 隐藏 ID ΔSR（Final-Round 轨道），按 L2（S1/S2）与 L3（S3）**分开**分析。
- **假设与否决阈值**：docs/HYPOTHESES_ZH.md（H1–H6）。
- **对照**：4 个脚本臂强制；LLM 必须报告相对最强简单替代（analytic_ridge、random）的位置。
- **失败分母**：全部 run 入分母；interrupted 的 run 续完后才计入，且标注经过中断。
- **推断**：检查点为聚类单位，按任务分层，配对 bootstrap + sign-flip；Holm 校正；预先指定主要比较（3 个以内）。

## 4. 本机资源
- Tier-0 全部是 CPU/numpy：单次 rollout 毫秒级；一个 run 的评测（16×R + 400×2 episode）< 2 s；**瓶颈是模型调用，不是算力**。作业 <0.5 GB，不需 memguard；构建检查点用 `nice -n 19 taskset -c 12-15`（避开其他 agent 的核）。
- GPU 本阶段不需要。官方基准阶段若用本机 GPU，按 ops-playbook：用户在用机器时降级（vram-frac 0.6、no-stats、throttle 0.3），用户宣布全速窗口才全速。

**必须记住的设计约束**：
1. **输入归一化必须折叠进 W1/b1**（可行性脚本已这样做），否则策略里有编辑者看不到的隐含预处理，“编辑的是完整策略”就不成立。

## 8. E1 结果（无额度；契约 v6；`runs/SUMMARY/baselines-v1-a1.md`、`baselines-greedy-v1-a1.md`、`noise_floor.json`）
588 个脚本臂 run（基线 306 + 贪心 282），全部 verified；独立复算 240 项检查零不一致。检查点 53 个：S0 4、S1 28、S2 9（c04-delay 无 S2）、S3 12（自然训练）。
**v1→v2 修订**：v1 的 S3 是“好策略+弥散噪声”（可被闭式重拟合去噪，不算健康策略），且 OOD 偏移过大把 S2 压到 SR=0；v2 重建 S3 并在 `select` 上重新校准 OOD。v1 结果保留为证据（`runs/baselines-v0/a2` 等，标 SUPERSEDED），不与 v2 混用。

起点（未编辑）隐藏成功率（ID / OOD）：

| 任务 | S1（植入） | S2（自然故障） | S3（自然健康） |
|---|---|---|---|
| c01-reach | 0.46 / 0.32 | 0.46 / 0.16 | 0.72 / 0.33 |
| c02-avoid | 0.30 / 0.15 | 0.32 / **0.00** | 0.72 / 0.42 |
| c03-hold | 0.56 / 0.50 | 0.55 / 0.30 | 0.86 / 0.36 |
| c04-delay | 0.41 / 0.28 | — | 0.70 / 0.23 |

各臂隐藏 ΔSR 均值（ID；括号内 OOD）：

| 臂 | S1 | S2 | S3 | 增益≥0.10 的 run 占比（S1/S2/S3） |
|---|---|---|---|---|
| null | 0 | 0 | 0 | 0 / 0 / 0 |
| random（5%·0.5σ，累积 4 轮） | −0.20 (−0.14) | −0.21 (−0.07) | −0.35 (−0.12) | .17 / 0 / .08 |
| random_greedy（同等反馈，小/大步长） | +0.01/0.00 | −0.01/−0.02 | −0.03/−0.08 | .12–.19 / 0–.04 / 0–.06 |
| analytic_ridge（特权专家标签） | **+0.49 (+0.39)** | −0.02 (+0.16) | **+0.17 (+0.49)** | 1.00 / .33 / .67 |
| **gain_greedy（单参数：整体缩放输出层 W3，同等反馈预算）** | +0.26 (+0.14) | **+0.27 (+0.21)** | +0.05 (+0.28) | — |
| oracle_restore（S1 真值，上界） | +0.50 (+0.39) | — | — | 1.00 / — / — |

读法：
1. **S1**：闭式解几乎等于神谕（+0.49 vs +0.50）。LLM 的“修复”必须和它比；超过它几乎不可能（神谕本身上限约 0.93），能报告的是“能否达到解析解水平”。
2. **S2**：闭式解不稳（9 个检查点从 −0.55 到 +0.54，仅三分之一增益≥0.10；c03-hold 平均 −0.36）——**区分度最大的位置**，也是 LLM 可能体现差异之处。
3. **S3**：自然健康策略仍可被特权闭式解改善（+0.17，OOD +0.49；12 个检查点范围 −0.04…+0.44）。含义：这些策略“欠训练”而非“饱和”；H3 的“增强”读数必须相对 analytic_ridge 报告，且 analytic_ridge 用了 LLM 没有的专家标签（蒸馏），只能当强参考，不当同台竞争者。c02-avoid 的 S3 上它没有增益（−0.02），因为专家上限只有 0.81。
4. **同等反馈的简单搜索≈0**：4 轮×16 episode 的反馈不足以让贪心随机搜索起作用，大步长还会变差；random 太破坏性，不算强对照。
5. **噪声**：53 个检查点、5 个互不相交 200-episode 集合，SR 标准差 ID 中位 0.030、最大 0.060，OOD 中位 0.028（二项上界 0.035）；判定带宽 δ=0.10 仍是安全的。
6. **残余局限**：c02 的 S2 在 OOD 上起点为 0（无分辨力）；S2 只有 9 个检查点、无 c04；S1 的 unit_sign_flip 在 c02/c03 不可行。

**E1 补充（2026-11-06，首次 Claude 冒烟之后）**：Sonnet 5.5·medium 的第一个冒烟 run 只写了一行 `W3[:, :] *= 1.3`，把隐藏 ID 成功率从 0.58 提到 0.96。据此新增对照臂 `gain_greedy`（49 个 run，全部 verified）。结果改变了对 S2 的解读：**S2（自然故障）上，一个单参数启发式就有 +0.27，反而优于闭式解（−0.02）**；所以 S2 不再是“只有 LLM 才可能修好”的位置，Claude 在 S2 上的成绩必须先与 `gain_greedy` 比较；S1 上 `gain_greedy`（+0.26）远低于闭式解/神谕（+0.49/+0.50），S1 仍有较大区分空间。冒烟成本实测：2 回合共 ≈900 输出 token、14 s、CLI 报告 ≈$0.07（订阅额度占比未知，需用户读数）。
