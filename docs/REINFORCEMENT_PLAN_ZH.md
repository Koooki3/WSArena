# 补强清单：构念效度 + 官方基准层（2026-11-06；待用户确认优先级）

目的：回答“完整做完后是否具有足够的科学/评估价值”（见对话评估）。两个最决定价值的缺口：**A 构念效度**——分数是否真的测到“读懂并改写权重”，而不是“按说明书写一个控制器”或“拧一个增益旋钮”；**B 官方基准层**——是否跨过玩具规模。每项给出：证据、做法、验收判据、成本、依赖。成本栏：**CPU** = 不耗订阅额度；**额度** = 需要 Claude 调用（CLI 报告成本，换算约 7 点 5h 窗口/$1）。

## A 构念效度
证据（来自 Pilot 与基线）：①Opus 在 c02-S2 上整体重写网络为手工 PD+避障控制器（frac_changed=1.0），更像“编译一个控制器进权重”；②单参数增益搜索在 S2 上 +0.27 > 闭式解 −0.02；③同一健康检查点上出现“不编辑 / 到 1.00 / 改坏”三种行为；④c01 对 Claude 饱和。

## B2 结论（2026-11-07）：OCBench 后端已完成，但**不能作为 Native 赛道任务**
- 后端：`official/ocbench_task.py`（4 项测试通过，确定性、并行=串行、归一化折叠、纯度）；任务 1 的目标（把唯一方块移到桌面中心 (0.425, 0, 方块静止高度)，成功半径 0.04 m）与 28 维观测布局已写入提示描述。
- **可行性实测**：脚本专家（`BlockController`）40/40 成功（平均 78 步）；但**普通 MSE 行为克隆的小 MLP 几乎全失败**：60 示范×400 epoch SR 0.02；400 示范（5.7 万样本）：宽度 24 → 0.00（200/600 epoch），宽度 64（6.5k 参数）→ 0.03/0.00；主要失败类型 `never_near_block`。原因推测：接触密集、多模态的分段专家动作被均方误差平均掉；OCBench 的官方做法是用大数据集与大网络/序列模型做离线 GCRL。
- **结论（如实）**：S1–S3 检查点**无法**用这种构造做出（目标成功率带不可达），因此 OCBench 暂**不进入 Native 赛道与主研究**；它保留为 **Probe/Agentic 赛道**（B3/B4）的候选：需要更大的、按官方配方训练的策略（可能要 GPU/集群，需另行请示），或改用流/扩散/动作分块策略。已作为负面结果记入局限，不再在 Native 里投入。
- 影响：官方基准层在 Native 赛道目前只有 **Meta-World（2 个任务）**；论文里要如实写“OCBench 在小网络 BC 设置下不可行”，而不是回避。
