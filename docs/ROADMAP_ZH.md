## 各阶段的判定与分支（先写规则，后看数）
- **P1 之后**：按 §5 结果类别表固定措辞出结论。若 C1/C2 均不成立 → 不追加 Tier-0 额度，转 P3（官方层）验证是否仅是 Tier-0 现象；若 WRI≈0（盲读≈完整）→ 论文头条改为“编辑能改善策略，但在小网络上不依赖读权重”，并把 P5（规模梯度）提到前面，因为“权重变大后读权重是否成为必要”是下一个关键问题；若 σ_run 大（>0.15）→ P3 重复数加倍、结论降级为“分布层”。
- **P2 之后**：若 64k 相对 32k 有 ≥0.10 的 ΔSR 差异 → 说明 Pilot 以前的数据受截断影响，Pilot 在报告中标注；否则一句话披露即可。
- **P3 之后**：官方层结论与 Tier-0 方向一致才写成“跨层稳健”；不一致如实写“Tier-0 不外推”。
- **P5 之后**：给出“读权重的有效性随宽度的退化曲线”（科学性与泛用性的核心图）；若 64 宽时仍可用而 128 宽超出上下文 → 标明 Native 赛道的容量边界，把更大网络交给 P6 的探针赛道。
- **P6**：只作独立赛道，不与 Native 混排；若工具权限审计不能做到服务端强制，则不上线该赛道（写成未来工作）。
- **停止规则**：任一批完成率 <50%、出现泄漏审计不过、或契约被迫变更 → 停、记录、先修再续；额度触线 → 保存并写交接记录，不改参数续跑。

## 排序（每个窗口一件事，窗口之间读数）
1. 窗口 A（本窗口，现 ≈53% 起）：P1 第 1 批（在跑）→ 读数 → P2（8 run）。
2. 窗口 B：P1 第 2–5 批（主 64 的前半）。
3. 窗口 C：P1 第 6–8 批 + 重复/盲读的一部分。
4. 窗口 D：P1 余下；P1 分析（C1–C3、σ_run、WRI、机制分层）。
5. 窗口 E–F：P3 探针 → Meta-World 主批（视周额度，必要时跨周）。
6. 之后：P4 → P5 → P6（按 P1 分支调整先后）；P7 全程并行；P8 在 P1–P5 齐后；P9 从现在起并行写（方法、相关工作、任务定义先写，结果节后填）。
