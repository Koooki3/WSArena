# Leaderboard and submission rules (draft)
**What can be submitted**: the complete run directory of an experiment (spec, per-round replies and results, raw event streams, `run.json`), produced by the released runner under a released contract version, with the output of `scripts/check_frozen.py`.
**Tracks (ranked separately)**: Native (weights in the prompt, no tools), Probe (read-only probes through the harness, no tools), Analytical and Agentic (not yet defined, listed so that nothing is mixed in by accident).
**Required for a result to be listed**: (1) every run verified by the leak audit and the tool-free audit, failed runs kept in the denominator; (2) the pre-registered checkpoint set for the track, no subset; (3) at least three independent runs per checkpoint for any ranking claim (single runs may be reported but are not ranked); (4) the report must include the attempt rate, the share of rounds truncated by the output cap, and the controls run on the same checkpoints; (5) the model, effort name and client version exactly as the client reports them.
**How results are reported**: gains with cluster-level confidence intervals, never a single total across tasks; ranks only as tiers when intervals overlap.
**What is rejected**: runs that used tools or code execution, hidden episodes seen by the editor, checkpoints chosen after seeing results, changed contract hashes without a version bump.
