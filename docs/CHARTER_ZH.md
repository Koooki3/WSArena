- **已知会踩的坑（本项目特有）**：
  1. 全局 `~/.claude/CLAUDE.md`、记忆与 skills 会被 `claude -p` 自动加载，污染被评测模型的上下文，也浪费额度 → 网关必须隔离（空工作目录 + 自定义系统提示 + `--setting-sources ""` + `--disable-slash-commands` + `--tools ""`），并在首个 run 前用探针测“看不到任何用户指令”。
  2. 高推理档可能耗尽输出预算而没产出补丁（社区实测）→ 失败类型分三类记录（预算耗尽/补丁无效/补丁有效但无改善），并做大输出上限的灵敏度子实验。
  3. 转述不可靠：ChatGPT 报告里的若干出处无法核实（见 PREMISE_CHECK）；结论只引已读一手的出处。
  4. “评测有缺陷”风险：维基记录 Chandan Singh 的 Claude 手写 transformer 结果存在评测弱点 → 隐藏集隔离、重复评测与独立复算是强制项。

## 4. 诚实条款

- T2：一个假设被 KILL 后，不在同一条线上事后放宽判据；看到结果后的重新解释只能作为新假设的动机。
- T3：所有偏离写进偏离表，只能单向加严。
- T4：失败运行（含预算耗尽、拒答、触限中断）永远留在分母里；不得通过重跑换掉。

## 7. 资源与预算
- 本机：WSL 11 GB RAM、RTX 4060 8 GB（桌面共用，当前已占约 3 GB）、20 核。被评测的小网络与 Tier-0 环境为 CPU 作业；≥0.5 GB 走 memguard；≥2 GB 先告知。
- 瓶颈是 **Claude 订阅额度**（Pro：5 小时窗口 + 周额度）。规则（来自全局 CLAUDE.md，只能更严）：
  - 读不到额度 → 按“窗口可能已用过半”处理：并行 ≤1，批量小，批后让用户读数；
  - 每批开始前与结束后各记一次额度读数（用户提供或工具读取）到 `runs/QUOTA_LOG.tsv`；
  - 触限（rate limit / usage limit）即停：保存 WIP 与续跑点，不循环重试，不设定时器；
  - 预留 ≥15% 的 5 小时窗口给主会话。
- 集群：暂无需求；若官方基准（OCBench / Kinetix）本机跑不动，再请示 MLDA/ROSE（ROSE 只用免费 QoS，MLDA 私密隔离，见 memory）。
- 记录预算：PARADIGM §5；每阶段一份 JSON + 一份摘要。
