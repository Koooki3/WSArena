# 记录与发布方法论：参考 VABAR（arXiv 2611.06881 与其项目网站）

来源（均经抓取代理读取原文，用户确认其为所指文章的主题）：论文 HTML、项目网站首页 / tasks.html / selflearning.html。

## VABAR 怎么组织和发布
1. **三面并举**：论文（arXiv）+ 项目网站（Overview / Benchmark Details / Case Study 三页）+ 代码仓库（网站标注分阶段放出）。
2. **先定位再展开**：用“它与相邻方向的区别”（Fixed Automation / Variational Automation / Generalist Robotics 三列对比）开篇。
3. **设计准则显式化**：7 条准则 + 任务的形式化定义 𝒯=(ℰ,ℛ,𝒜,𝒪,p𝒪,𝒮)；容许变化须满足 5 条原则。
4. **诊断式执行记录**：把失败归到最早能解释后续结果的层（感知 / 决策 / 物理交互 / 验证），并有“执行记录映射表”。
5. **难度分级 + 参考结果表**：每任务 L1/L2，附参考成功率与周期时间。
6. **结果按“零样本 vs 两轮执行反馈后”呈现**，多个模型并列，均值为多次运行。
7. **“基准发布了什么”清单表**（资产库、机器人、任务规范、物理引擎）。
8. **案例研究单独成页**：失败 → 诊断（物理真值视图）→ 新技能 → 结果。
9. 种子受控、重跑同一规格得到同一场景；BibTeX 随页给出。

## 它没做、我们要做得更严的
N=30 无置信区间、无种子数说明、无显著性检验；无 license、版本号、运行指南、排行榜与提交说明；变化分布的采样范围未公开。
