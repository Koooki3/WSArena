# 基准 v2 改进方案（草案，未冻结；2026-11-08；依据：主研究结果与 `reports/CHECKPOINT_SCREEN.md`）

状态：**DRAFT**。任何 v2 运行之前必须单独提交并冻结（同 PREREG 流程）；本草案不改变已冻结的 §11–§15。

## 1 要解决的问题（来自评判效力评估）
细排名不可靠（Tier-0 四臂排序 Kendall τ=0.59）；Meta-World 重测 r=0.27（53% 的检查点所有臂差不多、41% 所有臂≈0）；c01/c03 饱和；构念上“读权重”无平均贡献；泛用性不足。

## 2 方案（按优先级）
1. **报告尝试率与有效编辑率**（已实现 `scripts/analyze_screen.py` §3）：Meta-World 上 Opus 尝试率 100%、有编辑轮次占 81%，Sonnet 59%/38%；Tier-0 Opus 100%，Sonnet 81–94%。弃权与改坏分开呈现，不让“没动手”显得像“修不好”。
2. **检查点“头部空间”筛选，只用脚本对照**（不用 LLM 输出选题）：H = max(gain_greedy, tensor_gain_greedy, analytic_ridge, oracle_restore) 的增益，S1/S2 要求 H ≥ 0.10；S3 不筛（健康策略头部空间小是定义）。**验证结果（事后，主研究 33 个检查点）：部分有效**——Meta-World 里被筛掉的 3 个检查点完全无区分度（臂间极差均<0.05、67% 全部≈0），筛除合理；但保留下来的 14 个里仍有 36% 全部≈0，说明“脚本能改而 LLM 都不改”是**能力地板**而不是设计缺陷；Tier-0 里筛选无帮助（被筛 3 个反而区分度更高，n 太小）。结论：筛选只用来去掉“连脚本都没有提升空间”的死检查点，不能指望靠它消除地板效应。
3. **把“地板检查点”作为单列的“前沿集”**：对当前所有 LLM 都≈0 的检查点（Meta-World 约 41%）不从基准里删除，而是标为 frontier——对未来更强的模型才有区分度；报告里“当前可区分集”和“前沿集”分开给数字，**分档由脚本对照与预先规则决定，不由 LLM 结果事后挑**（避免循环论证；规则要在 v2 预注册里写明，如“H≥0.10 且某脚本臂增益≥0.10 而同层无 LLM 臂曾≥0.05”这类规则需先对 pilot 校准）。
4. **重复 ≥3 次**，细排名只报“高/中/低”档与置信区间，不给精确名次。重复数的成本：Tier-0 每臂每聚类 3 次约为当前的 1.5 倍。
5. **WRI 作为常规诊断**（盲读 + 重参数化），每次评测随附；规模阶梯（P5）与探针赛道（P6）回答其随宽度的变化。
6. **任务组合**：c01、c03 降为健全性检查（不进主比较）；主推 c02、c04、Meta-World；新增官方层任务需满足“脚本臂头部空间 + 非平凡 LLM 差异”的 pilot 校准。
7. **泛用性**：规模阶梯（宽度 24→128）、探针赛道（宽度 256/512）；语言/视觉网络列为明确边界与未来工作，不在 v2 内承诺。

## 3 不做什么
不用 LLM 结果挑检查点后再报这些检查点上的 LLM 优势；不为让 Meta-World 好看而降低难度；不合并 Tier-0 与 Meta-World 为单一总分。

## 4 成本与时机
v2 的新运行（3 次重复、更多官方层任务）估计 100–150 个运行，需要周额度重置后分批；先冻结本草案的规则，再启动。与 P5/P6 的主批合并排期。
